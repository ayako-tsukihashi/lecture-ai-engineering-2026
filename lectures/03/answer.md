# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：

「AIE2026の講座の宿題にある『3レベル』とは何ですか？」という質問について、第1回の実行記録と今回の実行結果を比較した。いずれも使用モデルは gemini-3.5-flash-lite である。

第1回の app.ask では、「基礎・初級」「応用・中級」「発展・上級」という一般的な難易度の区分として説明され、正確な内容は講座のシラバスや宿題ページなどで確認するよう案内された。

今回の app.agent では、講座の定義に沿って「基礎・実装・発展」と回答され、それぞれの内容に加えて、「どれか1つに取り組めばその回の宿題は完了する」というルールが明示された。また、回答の最後に関係する回として「第1回」が示された。今回の比較から、講座固有の質問に答える際には、モデルの一般的な知識に加えて、用語集などの根拠となる情報を参照できる仕組みが重要だと考えた。


- `--trace` で見えたツール呼び出し（ツール名と引数）：

「LoRAとQLoRAの違いは？」という質問では、次の2つの呼び出しを確認した。

search_glossary({'query': 'LoRA'})
search_glossary({'query': 'QLoRA'})

query に用語を1つずつ指定し、それぞれの定義と講義回を取得していた。最終回答では、LoRAの仕組みと、QLoRAではベースモデルの量子化によってメモリ使用量をさらに抑えるという違いが説明され、関係する回として「第2回」が示された。

また、「第2回の内容から確認問題を1問出して」という依頼では、追加したツールが次の引数で呼び出された。

make_quiz({'lecture': 2})

ツールの返り値には「『LoRA』の意味は？」という問題と、その答えとなる定義が含まれていた。ユーザー向けの最終回答では、LoRAの主な仕組みや特徴を説明する確認問題が提示された。


- 1つの質問での LLM 呼び出し回数（`requests`）：

LoRAとQLoRAの比較では、requests=2、tool_calls=2 であった。確認問題の出題では、requests=2、tool_calls=1 であった。

どちらも1つの質問に対してLLMが2回呼び出されていたが、ツールの呼び出し回数は異なっていた。この結果から、LLMの呼び出し回数とツールの呼び出し回数は別の指標であり、1回の質問でも、ツールの結果を利用して回答するためにLLMが複数回呼ばれることを確認した。


- 追加したツールと、docstring に書いた説明：

app/tools.py に make_quiz(lecture: int) -> str を追加した。load_glossary() で読み込んだ用語集から、指定された講義回に一致する用語を集め、random.choice() で1つ選択する。その用語について「○○の意味は？」という問題を作り、用語の定義を答えとして、question と answer を含むJSON形式の文字列で返すようにした。また、該当する用語がない場合には、エラーで終了せず、用語が見つからないことを返す処理を加えた。

docstringには、「指定した回の用語から確認問題を1問作り、答えとともに返す」と機能を説明し、「第2回の確認問題を出して」のように、指定した回の復習問題を求められたときに使うことを記載した。引数 lecture についても、講義回の番号であり、第2回なら 2 を指定することを明記した。

app/agent.py では、agent.tool_plain(tools.make_quiz) によって登録した。--list-tools を実行し、既存の search_glossary、get_lecture_summary と合わせて3つのツールが表示され、make_quiz の説明と整数型の引数 lecture を確認できた。さらに、--trace で実際の呼び出しを確認し、uv run pytest -q では 16 passed in 4.37s となり、16件すべてのテストが成功した。


## 宿題

- 取り組んだレベル：発展（a：Google ADKでエージェントを作り直す）


- やったこと：

演習で作成したPydantic AI版の学習支援エージェントを基に、エージェントを組み立てる部分をGoogle ADKで実装した。

adk_agent/glossary_agent/agent.py と adk_agent/glossary_agent/__init__.py を作成し、既存の app.agent から INSTRUCTIONS、app.tools から search_glossary、get_lecture_summary、make_quiz を読み込んだ。モデルには、演習と同じ gemini-3.5-flash-lite を指定した。

ADK版では、Agent の instruction に指示文を、tools に3つの関数をリストとして渡し、root_agent を定義した。Pydantic AI版の instructions や agent.tool_plain(...) と、指示・ツールの指定方法が異なることを確認した。

リポジトリ直下で、次のコマンドを使って起動した。

PYTHONPATH=. uv run --with google-adk adk run adk_agent/glossary_agent

演習と同じ内容の3つの質問を入力し、回答を比較した。前の会話の影響を避けるため、質問ごとにADKを終了して起動し直し、新しい対話セッションで実行した。


- 結果：

① 宿題の「3レベル」について

「AIE2026の講座の宿題にある『3レベル』とは何ですか？」と質問すると、「基礎・実装・発展」の3つが示され、「どれか1つに取り組めば、その回の宿題は完了する」と回答された。また、関連する回として「第1回」が示された。

主要な内容はPydantic AI版と一致していた。ADK版では、基礎について「用語や概念の理解」と補足するなど、表現には多少の違いがあった。

② LoRAとQLoRAの違いについて

「LoRAとQLoRAの違いは？」と質問すると、LoRAは事前学習済みの重みを固定し、更新分を低ランク行列で表して学習する手法であり、QLoRAはベースモデルを量子化してメモリ使用量を抑えたうえでLoRAによる学習を行う手法であると説明された。関連する回は、Pydantic AI版と同じ「第2回」であった。

両者の違いに関する主要な説明は共通していた。ADK版では、LoRAがPEFT（Parameter-Efficient Fine-Tuning）の一手法であることや、アダプタを小さなファイルとして保存できる点も補足されていた。

③ 第2回の確認問題について

「第2回の内容から確認問題を1問出して」と依頼すると、ADK版では「『事前学習』の意味は何でしょうか？」という問題が提示された。さらに、大量のデータを使ってモデルが最初にどのような予測を行うかを考える、というヒントが添えられ、最後に「第2回」と表示された。

Pydantic AI版ではLoRAの主な仕組みや特徴を説明する問題が出題されていたため、今回は出題された用語と、ヒントの有無に違いが見られた。両者とも、ユーザー向けの最終回答には解答本文を含めず、確認問題を提示していた。

- 気づき・疑問：

指示文とツールの処理を再利用することで、エージェントを組み立てる部分を別のフレームワークへ移せることが分かった。Pydantic AIとADKでは指示やツールの指定方法、起動方法が異なるが、既存のPython関数をツールとして利用する構成は共通していた。

同じモデル・指示文・ツールを使用しても、説明の詳しさや補足、確認問題の見せ方には違いが見られた。一方で、宿題の3レベルやLoRA・QLoRAの違いに関する主要な説明は、おおむね一致していた。

make_quiz には用語をランダムに選ぶ処理があるため、出題された用語の違いだけで、フレームワークによる性能差を判断することはできない。また、今回は各質問1回の比較であり、モデルの生成の揺らぎや実行設定の違いも考慮する必要がある。

今回保存したADKのCLI出力は回答本文が中心であり、実際のツール名・引数・呼び出し回数までは確認していない。そのため、回答に「講座の用語集によると」と書かれていることだけを根拠に、検索ツールが実行されたとは断定できない。回答内容の比較と、実行ログによるツール利用の確認を分けて考えることが重要だと感じた。
